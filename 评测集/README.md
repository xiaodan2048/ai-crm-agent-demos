# 评测集

三个作品（4 个 Dify 应用）的全部测试用例和一个自动评测脚本，放在一起方便复现。

> 所有用例、会话和数据都是虚构的。

## 文件

| 文件 | 内容 | 用例数 |
|---|---|---|
| [`外呼Agent-测试用例.csv`](外呼Agent-测试用例.csv) | 5 类测试用户的开场信息、逐轮说法、要测什么、预期的小结字段、禁用词 | W1–W5 |
| [`坐席助手-测试用例.csv`](坐席助手-测试用例.csv) | 顾客消息、订单状态、预期问题类型和依据条款；Z2 含一次 `/小结` | Z1–Z5 |
| [`会话复盘-测试用例.csv`](会话复盘-测试用例.csv) | 6 段完整会话，预期原因标签、是否解决、风险类型、是否需人工复核 | F1–F6 |
| [`主管周报-测试用例.csv`](主管周报-测试用例.csv) | 10 条复盘结果作为输入，预期要点 | B1 |
| [`run_eval.js`](run_eval.js) | 自动评测脚本：在浏览器里跑完全部用例、自动打分、导出结果表 | — |

CSV 用 Excel、Numbers 或飞书表格打开即可。

## 怎么评测

### 方法一：手动（最直观，适合面试前自己体验）

1. 打开 Dify 里的应用，点右上角「预览」。
2. 按 CSV 里的「开始节点输入」填好信息，再按「用户说的话」一轮一轮输入。
3. 对照「预期」列看回复和小结是否一致。

### 方法二：自动脚本（适合改了提示词后做回归）

不需要安装任何东西，大约 8–10 分钟跑完全部用例。

1. 用 Chrome 打开 [cloud.dify.ai](https://cloud.dify.ai) 并登录，确认 4 个演示应用都在「工作室」里，名字分别是：外呼Agent-演示、坐席助手-演示、会话复盘-演示、主管周报-演示。
2. 按 **Option + Command + J**（Windows 是 Ctrl + Shift + J），打开「控制台（Console）」。
3. 打开 [`run_eval.js`](run_eval.js)，点 GitHub 页面右上角的「复制」按钮，复制全部内容。
4. 在控制台里粘贴，按回车。
   - 如果 Chrome 提示不允许粘贴，按提示先输入 `allow pasting`（或"允许粘贴"）并回车，再粘贴一次。
5. 控制台会显示进度（橙色的「[评测]」字样）。跑完会自动下载一个「评测结果-日期.csv」，控制台也会打印汇总表。

只想跑几个用例：把脚本开头的 `const ONLY = [];` 改成例如 `const ONLY = ['W4', 'F1'];` 再粘贴。

### 结果表怎么看

下载的 CSV 分两部分：

- **上半部分是检查结果**：每个用例的每一项检查，结果是「通过」「不通过」或「需人工看」。
- **下半部分是对话记录**：每个用例每一轮的输入和完整回复，方便核对。

| 结果 | 含义 |
|---|---|
| 通过 / 不通过 | 脚本能自动判断的项，比如小结里的续费意向、依据条款编号、风险类型 |
| 需人工看 | 脚本判断不了的项，比如"有没有乱承诺"。脚本只查禁用词，没查到也需要人读一遍对话确认 |
| （参考）开头的项 | 不计入得分，例如外呼的"不续原因"，用来观察稳定性 |

## 自动检查的规则

| 应用 | 自动检查 |
|---|---|
| 外呼 Agent | 意向判断（小结的续费意向）、转人工/勿扰（小结字段）、小结 6 个字段是否齐全、对话里是否出现禁用词 |
| 坐席助手 | 问题类型是否都识别到、依据条款编号是否引用正确、`/小结` 字段是否齐全 |
| 会话复盘 | 原因标签、是否解决、风险是否漏标、是否多标、是否需人工复核 |
| 主管周报 | 关键数字和坐席是否出现、是否编造了输入里没有的坐席；具体数字需人工核对 |

## 注意

- 脚本测的是应用的**草稿版本**，就是你在编排页面里看到的最新内容，改完提示词不用发布就能测。
- 脚本调用的是 Dify 网页自己的接口（和你在预览里点发送一样）。Dify 升级后接口可能变化，脚本到时可能需要调整。
- Sandbox 套餐的知识库检索有频率限制，脚本会自动放慢；遇到限流会等 65 秒重试。
- 如果中途提示"登录已过期"，刷新 Dify 页面再运行一次，已完成部分的结果会先导出。
- 只往控制台粘贴你信任的脚本。这个脚本只读取和调用你自己账号里的 Dify 应用，不会把数据发到别处。
- 多轮对话靠"上一条消息 ID"串联。早期版本的脚本漏了这一点，模型看不到前文，导致误判（详见 [`01-renewal-call-agent/评测结果.md`](../01-renewal-call-agent/评测结果.md)）。现在的脚本已经修好。

用例数据同时存在 CSV 和 `run_eval.js` 里。改用例时，CSV 和脚本里的 `CASES` 要一起改，否则两边会对不上。
